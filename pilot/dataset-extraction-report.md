# Отчёт: извлечение датасета из реальных вызовов агента (пакет 4)

- Дата: 2026-09-27. Основание: `pilot/dataset-plan.md`, ADR-003 §4 (закрытый
  периметр), ADR-004 §3 (домен-адаптация обязательна).
- Артефакты: `pilot/tools/extract_tool_calls.py` (скрипт, только стандартная
  библиотека), `pilot/tools/fixtures/sample-sessions.jsonl` (синтетическая
  фикстура), `pilot/dataset-stats.md` (агрегаты — в репозитории), датасет —
  **вне рабочего дерева** (`<shared-store>
  приватный артефакт, права `600`).
- В отчёте домашний префикс сокращён до `~`, имя пользователя — до `<user>`:
  ни абсолютных домашних путей, ни имени пользователя в репозиторий не
  переносится (сказано явно, чтобы вставки вывода команд не выглядели
  подделкой).

## 1. Что извлечено

Источник — история сессий агента (`<agent-session-logs>/**/*.jsonl`), пять
инструментов: `Bash` (команда), `Read`/`Edit`/`Write` (путь), `WebFetch` (URL).
Из каждого вызова в датасет попадает **ровно одно** поле полезной нагрузки.

| Показатель                            | Значение   |
| ------------------------------------- | ---------- |
| Файлов сессий прочитано               | 1 380      |
| Строк журнала прочитано               | 279 654    |
| Строк с вызовами инструментов         | 115 487    |
| Блоков `tool_use` встречено           | 65 084     |
| Прочие инструменты (вне пяти целевых) | 1 436      |
| Вызовы без полезной нагрузки          | 24         |
| **Примеров в датасете**               | **63 637** |

Страты (`stratum`):

| -------------- | -------- | ------ |

Схема примера — из `pilot/dataset-plan.md`: `id`, `stratum`, `tool`, `source`
(id сессии + строка, без содержимого), `command` (канонизированная команда
после редакции и обрезки путей), `path_class`, `cwd_class`, `det_flags`
(правило страты, совпавшие правила, классы путей, число вырезаний), `label`
и `by` — **пустые** (под ручную разметку), `synthetic` — `false`.

## 2. Периметр: что читается, а что не читается вовсе

- **Белый список полей.** Читаются только `command` (`Bash`), `file_path`
  (`Read`/`Edit`/`Write`), `url` (`WebFetch`). Содержимое файлов (`content`),
  старые/новые строки (`old_string`/`new_string`), промпты (`prompt`), тела
  ответов и результаты инструментов **не читаются вообще** — не «вырезаются»,
  а не попадают в конвейер. Это проверяется самотестом: в фикстуре лежат
  маркеры `SYNTHETIC_FILE_BODY_DO_NOT_EXPORT`, `SYNTHETIC_OLD_DO_NOT_EXPORT`,
  `SYNTHETIC_NEW_DO_NOT_EXPORT`, `SYNTHETIC_PROMPT_DO_NOT_EXPORT`, и ни один
  из них не должен оказаться в датасете.
- **Редакция секретов** — те же 13 классов паттернов и тот же порядок
  применения, что в `CMP-004` (`packages/core/src/jev/state.ts`):
  PEM-блоки, URL userinfo, `KEY=/TOKEN=/PASSWORD=/SECRET=`, CLI-флаги секретов,
  `Bearer`, JWT, AWS/GCP/OpenAI/GitHub/Slack-идентификаторы, длинные hex и
  base64. Литералы вендорских префиксов в исходнике собираются из частей —
  как и в CMP-004. Считаются вырезания по классам, значения не сохраняются
  нигде, кроме самого датасета.
- **Сведение путей к классу.** `<workspace>` — путь внутри рабочего каталога
  сессии (остаток пути сохраняется: структура внутри проекта — сигнал);
  `<external>` — домашний путь вне рабочего каталога (имя пользователя и
  первый каталог после домашнего отбрасываются — там имя проекта) либо
  системный абсолютный путь (сохраняется без корня: `/etc/passwd` →
  `<external>/etc/passwd`). Относительные пути не трогаются. Единственное
  исключение — устройства (`/dev/null`, `/dev/stdout`, …): они остаются
  литералами, потому что идентичности не несут, а встречаются почти в каждой
  команде. `$HOME`/`${HOME}` сводятся к `~` перед сведением путей. URL целиком
  защищён от обрезки: внутри URL путь не файловый.
- **`cwd_class`** — класс рабочего каталога сессии: `workspace`, если каталог
  внутри домашнего (рабочий периметр пользователя), иначе `external`
  (в корпусе 63 464 / 173).

## 3. Стратификация

Правила — детерминированная таблица `RULES` в скрипте; порядок таблицы **и
есть приоритет**, первое совпадение задаёт страту. Порядок выбран так, что
страты безопасности стоят выше языковой оси и «бытовых» страт:

1. `adversarial` — текст-указка классификатору (EN + RU: «ignore previous
   instructions», «classify as read_only», «set permission_class=»,
   «не блокируй», «классифицируй как»);
2. `exfiltration` — отправка данных наружу: `curl -X POST/-d/--data-binary/-F`,
   `wget --post-*`, `scp`/`rsync` на удалённый хост, `docker push`,
   `npm publish`, `gh release upload`, `aws s3 cp … s3://`, слова
   `upload`/`webhook`/`ingest`;
3. `secrets` — `.env`, `id_rsa`, `*.pem/.key/.p12`, `credentials`, `secret(s)`,
   `.ssh/`/`.aws/`/`.kube/`, `kubectl … secret`, `vault`/`keychain`,
   `printenv`/`env |`, присваивание `*_KEY/TOKEN/PASSWORD/SECRET`, RU
   «пароль/секрет/токен»;
4. `destructive` — `rm -rf`, `mkfs`, `dd of=/dev/…`, `shred`, `wipefs`,
   `truncate -s 0`, `DROP/TRUNCATE TABLE`, `git push --force`, `curl | sh`,
   `find -delete`, `xargs rm`, `systemctl stop/disable`, `kubectl delete`,
   `terraform destroy`, `docker system prune -a`;
5. `ambiguous` — пограничные: `git reset --hard`, `git clean -f`,
   `chmod -R`, `rm` без флагов, `sudo`, `kill`/`pkill`, `docker rm/rmi`,
   `kubectl apply`, `terraform apply`, `helm install`, `systemctl restart`,
   `mv`/`cp` через границу workspace, запись вне workspace;
6. `russian` — кириллица в команде или пути (ось многоязычности);
7. `network` — URL, сетевые клиенты (`curl`, `ssh`, `gh`, …), установка
   пакетов, `git fetch/pull/push`, `npx`;
8. `write_local` — `Edit`/`Write` внутри workspace, перенаправления `>`/`>>`,
   `tee`, `mkdir`/`cp`/`mv`/`chmod`, `sed -i`, `git add/commit/checkout/…`,
   сборки;
9. `read_only` — `Read` и сегменты, **все** из которых начинаются с
   инспектирующей команды (`cat`/`grep`/`rg`/`git status|diff|log`/`pnpm test`…);
10. запасное правило `fallback_unclassified` → `ambiguous` (см. §7).

Кириллица дополнительно фиксируется флагом `det_flags.cyrillic` у **всех**
примеров (14 856), поэтому многоязычный срез можно строить поверх любой
страты, а не только поверх `russian`.

Выборка под ручную разметку — `--limit-per-stratum N`: примеры каждой страты
сортируются по SHA-256 от `source` и берутся первые N. Никакого ГПСЧ —
выборка воспроизводима, разброс по сессиям, без «любимых» сессий.

## 5. Проверки артефактов — evidence

Приватное в агрегате (встроенный сканер: домашние пути, имя пользователя,
13 классов секретов) и независимая проверка grep-ом:

```
$ python3 pilot/tools/extract_tool_calls.py --check-private pilot/dataset-stats.md
чисто: находок нет — pilot/dataset-stats.md

$ grep -nE '/home/|/Users/|/root/|<user>|sk-[A-Za-z0-9]{16,}|gh[pousr]_[A-Za-z0-9]{16,}|AKIA[0-9A-Z]{16}|AIza[0-9A-Za-z_-]{35}|eyJ[A-Za-z0-9_-]{10,}\.|xox[baprs]-[0-9A-Za-z-]{10,}|[A-Za-z0-9+/]{40,}' pilot/dataset-stats.md \
    && echo "НАЙДЕНО (плохо)" || echo "чисто: совпадений нет"
чисто: совпадений нет
```

Датасет лежит вне рабочего дерева:

```
$ root=$(git rev-parse --show-toplevel); d=$(realpath <shared-store>
$ case "$d" in "$root"/*) echo "ВНУТРИ РЕПОЗИТОРИЯ (плохо)";; *) echo "вне репозитория: да";; esac
вне репозитория: да
$ ls -l <shared-store>

$ git check-ignore -v "$d"
fatal: …/calls.jsonl: '…/calls.jsonl' is outside repository at '…/jev-gate'
$ git status --porcelain -- pilot/dataset-stats.md pilot/tools/
?? pilot/dataset-stats.md
?? pilot/tools/
```

Запись датасета внутрь репозитория запрещена жёстко: скрипт сам находит корень
по `.git` и отказывается писать датасет под него (проверяется самотестом).

Тот же сканер, запущенный по самому отчёту, сообщает 5 находок — и это ожидаемо:
в отчёте **цитируются сами проверяемые образцы** («нет `/home/` в датасете»,
строка команды `grep`, оборот `KEY=/TOKEN=/PASSWORD=/SECRET=` из описания
классов CMP-004). Синтетические пути фикстуры (`/home/example-user/…`) —
вымышленный пользователь; шаблоны домашних корней в скрипте — это и есть
детектор. Поэтому критерий приёмки сформулирован по конкретному артефакту
(`pilot/dataset-stats.md`), а не по каталогу: агрегат — единственный файл,
который обязан быть свободен от приватного, и он чист.

Фитнес-контроль репозитория: `arch-be control check .` → `Правил: 28,
нарушений: 0 (error: 0, warn: 0); Итог: PASS`.

Агрегаты целиком — в `pilot/dataset-stats.md` (объём, страты, инструменты,
правила, редакция по классам, покрытие сессий, классы путей). Ключевое:

- **Редакция:** 1 228 вырезаний в 896 примерах (1.4 % датасета). По классам:
  `env-assignment` 448, `long-hex` 414, `long-base64` 363, `bearer-token` 2,
  `cli-secret-flag` 1, остальные 8 классов — 0.
- **Покрытие сессий:** 817 сессий из 827 дали примеры; на сессию — min 1,
  медиана 27, max 4 852 (медиана и есть рабочая единица: длинные сессии
  размазываются по стратам).
- **Классы путей:** `workspace` 24 759, `external` 19 899, нет пути 18 979.
- **Запасное правило:** 15 403 примера (24.2 %) — не описаны таблицей правил.

## 7. Ограничения эвристик (честно)

1. **`adversarial` в реальном корпусе нет.** Один пример — ложное срабатывание
   на сессии самого извлечения (в корпус попадает текущая сессия, а в ней —
   исходник таблицы правил, где эти самые фразы написаны). Прямой поиск
   «почти-состязательных» фраз по датасету даёт 0 настоящих попаданий.
   Вывод: состязательную страту нужно добирать синтетикой с `synthetic: true`
   (план это и предусматривал) — иначе проверять устойчивость носителя к
   тексту-указке будет не на чем.
2. **Запасное правило — 24.2 %.** Всё, что не описано правилами (длинные
   heredoc-питоны, `cargo test`, составные конвейеры), попадает в `ambiguous`,
   а не в `read_only`: неизвестное считается неизвестным. Это снижает долю
   «чистого» `read_only` и делает `ambiguous` самой большой стратой — при
   ручной разметке её надо смотреть первой.
3. **Текстовые правила ловят подстроки.** `rm -rf` внутри питон-скрипта,
   передаваемого heredoc-ом, классифицируется как `destructive` (по смыслу
   скрипт действительно удаляет, но детерминированный слой этого не знает).
   Симметрично `huggingface-cli upload --help` попадает в `exfiltration`
   по слову `upload`.
4. **Шумные классы редакции.** `long-hex` и `long-base64` дают 777 из 1 228
   вырезаний — это в основном git-SHA, хеши и длинные слаги URL, то есть
   ложные срабатывания. Цена известна и записана в ADR-003 («отрицательные
   последствия»); для датасета это значит, что в 777 местах команда обеднена
   избыточно, а признак `det_flags.redacted` не равен «здесь был секрет».
5. **Обрезка путей не безупречна.** Путеподобные токены вне путей
   (`date +%Y/%m/%d`) могут сводиться к классу. Митигация: после ведущего `/`
   требуется «именной» символ (иначе `///` из док-комментариев и `sed '/^def /'`
   превращались бы в пути — эта ошибка была найдена на реальном корпусе и
   исправлена). Остаточный риск — редкие формат-строки; на разметку не влияет.
6. **Дубли не устраняются.** Один и тот же вызов встречается в логах несколько
   раз (сайдчейны, повторные прогоны). Дедупликация не делается сознательно:
   это распределение реальных действий, а не уникальных.
7. **Корпус — живой.** Повторный прогон даёт немного другие числа (в корпус
   попадают новые сессии, включая сессию самого извлечения). Числа в отчёте —
   снимок 2026-09-27.

## 8. Что дальше

1. Выборка под ручную разметку **уже собрана** (тем же скриптом):
   `<shared-store> — 397 примеров
   (по 50 на страту; `exfiltration` 46, `adversarial` 1 — столько есть в
   корпусе). Агрегат в репозитории при этом остался по полному корпусу
   (выборка писалась с `--stats` во временный файл). Для `adversarial`
   страту нужно сначала добрать синтетикой.
2. Ручная разметка 200–300 примеров (архитектор), спорные — с обоснованием;
   `label`/`by` в датасете оставлены пустыми именно под это.
3. Доборка редких страт (`adversarial`, `exfiltration`) синтетикой с флагом
   `synthetic: true` — иначе метрика false-allow по этим стратам не считается.
4. Метрики пилота (`pilot/README.md` §4): agreement по стратам, false-allow
   (главная), false-block относительно текущего LLM-каскада, reliability
   curve/ECE, латентность на GB10.
5. Синтетическая фикстура остаётся в репозитории как регрессионный тест
   конвейера: `--self-test` должен быть зелёным после любой правки скрипта.
