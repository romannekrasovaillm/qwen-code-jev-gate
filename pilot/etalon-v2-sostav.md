## Главное наблюдение: эвристика страт переоценивает риск

| Страта эвристики | Взято на разметку | Что оказалось по сути                                                                             |
| ---------------- | ----------------- | ------------------------------------------------------------------------------------------------- |
| `destructive`    | 38                | `write_local` в большинстве: удаление временных каталогов, кэшей, артефактов сборки, логов        |
| `exfiltration`   | 38                | `write_local`/`read_only`: правки `answer.md`, расчёты, локальные документы — передачи наружу нет |
| `secrets`        | 38                | почти все `read_only`: анализ файлов бенчмарка; секреты не читаются                               |
| `ambiguous`      | 38                | `read_only` (справки, `sed`/`grep`)                                                               |

Следствия:

1. **Реально разрушительных команд в корпусе агента мало** (класс `destructive` — 2 % разметки). Агент в основном работает с временными и восстанавливаемыми артефактами; настоящие необратимые операции редки. Это важно для приоритетов гейта: оптимизировать «ловлю разрушения» на этом корпусе почти нечего, зато ложные блоки на рутине дороги.
2. **Эвристика страт годится для отбора кандидатов, но не для метрик.** Все метрики считаются против ручного эталона, а не против страты — иначе мы измеряли бы качество эвристики, а не модели.
3. **Страта `exfiltration` в реальном корпусе практически отсутствует** (46 примеров по агрегатам, из них при разметке — ни одного истинного случая отправки наружу). Для честного замера по этому классу нужны либо синтетика, либо данные из другого контура.

## Что это меняет в плане

- Добор слабых страт выполнен (эталон вырос 275 → 396), но выявил не «мало данных», а **смещение эвристики**: класс `destructive` в эталоне малочислен не потому, что мы не добрали, а потому что таких команд в работе агента действительно мало.
- Для домен-адаптации это означает: обучающая выборка должна включать **синтетику по редким опасным классам** (`destructive`, `exfiltration`), иначе модель не увидит их вовсе. Синтетика помечается (`synthetic: true`) и учитывается отдельной строкой в метриках — как уже сделано для `adversarial`.
- Критерии приёмки из C36 не меняются: метрики считаются по эталону, включая редкие классы, с обязательной разбивкой по стратам.
