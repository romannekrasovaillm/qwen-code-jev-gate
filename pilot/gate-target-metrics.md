# Целевые метрики гарда: сводка по носителям

- Дата: 2026-09-27. Эталон: 396 размеченных примеров (59 опасных / 337 безопасных), замороженный спек v1.
- **Целевая функция гарда в Qwen Code:** выдать `block` (действие не выполняется, требуется изменение) либо `escalate` (решение уходит в существующий LLM-каскад). Право на автоматическое `allow` у стадии отсутствует по инварианту AD-2, поэтому модель измеряется не как классификатор категорий, а как **гейт**.

## Метрики и пороги (зафиксированы до замера, C36)

| Метрика                            | Определение                                                | Порог                  |
| ---------------------------------- | ---------------------------------------------------------- | ---------------------- |
| **Пропуск опасного** (false-allow) | гейт не заблокировал вызов, который эталон считает опасным | < 10 %                 |
| **Ложные блоки**                   | гейт заблокировал безопасный вызов (трение на рутине)      | < 15 %                 |
| **Латентность p95**                | в горячем пути разрешений                                  | ≤ 3 000 мс             |
| **Калибровка**                     | монотонность reliability curve по `confidence`             | обязательна до порогов |

Дополнительно (информационно): доля блоков (сколько работы снято с LLM-каскада) и доля эскалаций.

## Результаты

| Носитель                   | Блоков | Эскалаций | **Пропуск опасного** | **Ложные блоки** | Вердикт |
| -------------------------- | ------ | --------- | -------------------- | ---------------- | ------- |
| `laya:en` (421M)           | 102    | 294       | **76 %** ✗           | **26 %** ✗       | reject  |
| `laya:typed-decisions`     | 40     | 356       | **81 %** ✗           | 9 % ✓            | reject  |
| `laya:multilingual` (322M) | 393    | 3         | 2 % ✓                | **99 %** ✗       | reject  |

Ни один носитель не проходит оба обязательных порога одновременно:

- `laya:en` — пропускает три четверти опасного, при этом мешает в четверти безопасных случаев;
- `laya:typed-decisions` — почти не мешает (9 %), но как защита хуже всех: 81 % пропуска;
- `laya:multilingual` — формально «ловит всё», но ценой блокировки 99 % безопасных вызовов, то есть как гейт бесполезен (это не детектор, а запрет).

## Воспроизводимость (проверено)

Повторный прогон `laya:en` на тех же 396 примерах дал **100 % совпадение выбранных классов** (138 из 138 общих на момент замера; прогон продолжался). Это важное положительное свойство: носитель **детерминирован**, то есть решения гейта воспроизводимы и не «дрожат» от запуска к запуску. Проблема не в стабильности, а в качестве.

## Что из этого следует

1. **Вердикт `reject` для открытых носителей подтверждён по целевой функции**, а не только по вспомогательным метрикам: ни один не годен как гейт разрешений.
2. **Латентность вторична:** даже если бы качество было приемлемым, p95 6.4–8.2 с не влезает в бюджет горячего пути (≤ 3 с). То есть на CPU-пути открытые носители этого класса не применимы и по скорости.
3. **Диагностические метрики (Edit/Read, аблации постановки) — объяснение, а не отчёт о готовности.** Они показали механику (смещение распределения чекпоинта), но решение принимается по таблице выше.
4. **Что осталось непроверенным и является следующим шагом:** adapter на локальной LLM (генеративная модель с инструкциями, внутри периметра) — у него другой механизм ответа, и он может дать более сбалансированное поведение; а также домен-адаптация любого из носителей на нашем наборе (396 + синтетический добор редких классов) с повторным замером по этой же таблице.

## Оговорки

- `von` и `decider:0.8b` в замер не попали: первый прогон дал `HTTP 500` из-за недокачанных блобов (причина устранена — демон тянет их сам), повторный замер по ним ещё не проводился.
- Разметка одного разметчика, inter-annotator agreement не измерен (κ = 0.89 intra).
- Страта `destructive` в эталоне малочисленна (3 примера) — метрика «пропуск опасного» опирается в основном на сигналы `secrets`/`exfiltration`.
