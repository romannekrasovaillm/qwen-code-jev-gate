Ключевой практический вывод: **связка Ollaya (сервер) + Laya (модель) закрывает целевую архитектуру без единой строки нового сетевого кода** — наш бэкенд `JevBackend` уже параметризуется `baseURL`, а форма `/v1/systemone` совпадает с нашим контрактом (ADR-004 §2).

## Кандидаты пилота (порядок включения)

1. **`laya-local`** — Ollaya + Laya (ONNX, Apache-2.0). Приоритет: arm64-бинарь, TypeSafe-wire, заявленная калибровка (RLCD), многоязычность (тег `ru`/51 язык у multilingual-варианта) — критично, потому что русскоязычные аргументы у нас обязательная страта.
2. **`kev-local`** — Kev-4B через `kev.serve` (Apache-2.0, 4B, калибруется temp-fit). Второй голос: 4B-класс качества, но `en`-центричен и тяжелее для горячего пути.
3. **`llm_adapter`** — локальная LLM (vLLM/llama.cpp) на те же типизированные вопросы — контроль «нужна ли вообще специализированная decision-модель».
4. **`baseline_ml`** — эмбеддинги + логистическая регрессия — обязательный дешёвый контроль (методика `jev-pilot-harness`).
5. **`existing_llm`** — текущий LLM-классификатор Qwen Code — источник эталона и сравнения по латентности/цене.

## Непроверенное / риски (обязательные к снятию до боевого включения)

- **Латентность на ARM64 без CUDA**: релизная CUDA-сборка Ollaya — только `linux-amd64`; на GB10 доступен arm64-бинарь (CPU/ONNX). Заявленные 8–10 мс измерены на RTX 4090 — на нашем железе ожидаемо существенно больше. Бюджет гейта 1.2 с выглядит достижимым для 421M-энкодера, но это **гипотеза**, а не факт: измеряем в пилоте (p50/p95/p99).
- **Docker-образ `ghcr.io/ollaya-dev/ollaya:cuda`** — архитектура образа не подтверждена (на GB10 нужен arm64+CUDA); `[ТРЕБУЕТ ПРОВЕРКИ]`.
- **Kev-4B**: латентность и VRAM на коротком state (300–500 токенов, 5 вопросов) не опубликованы; `[ТРЕБУЕТ ПРОВЕРКИ]`.
- **Калибровка**: Laya заявлена калиброванной (ECE после temp-fit 0.081 по разбору), Kev — temp-fit per checkpoint; для остальных — энтропийная уверенность. До своей reliability curve пороги не ставим (ADR-004 §5).
- **Домен «безопасность вызова инструмента»**: прямых данных ни у одного носителя нет; все наши категории проверяются zero-shot → обязателен свой курированный eval.
- **Русскоязычный tool-safety**: данных нет ни у кого, включая мультиязычную Laya; страта в пилоте обязательна.
- **Лицензии**: OpenJev (CC-BY-NC-4.0) и Nimble (лицензия не определена) в продуктовый контур не допускаются (AD-11).

## Что это меняет в проекте

- ADR-004 дополнен разделом о выборе носителя по итогам разведки.
- В спайн добавлен **AD-11 (лицензионный фильтр)**: в целевой контур допускаются только перииссивные лицензии; NC/неопределённые — только вне продуктового контура и не в фикстурах.
- Дельта-задача после walking skeleton: бэкенд `local-systemone` (loopback `http://127.0.0.1:11435`, `GET /v1/models` для версии весов в журнале, health-check, таймаут, circuit breaker), удаление вендорского бэкенда из целевого кода.
