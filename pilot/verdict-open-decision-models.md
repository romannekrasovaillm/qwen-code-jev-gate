# Вердикт: почему открытые decision-модели не годятся в гард Qwen Code

- Дата: 2026-09-27. Основание: замеры на эталоне 396 размеченных примеров (`pilot/gate-target-metrics.md`), диагностика аблаций (`pilot-report-06`), проверка воспроизводимости.

## Терминологическая точность (важна для любых выводов)

**Тестировался не Jev.** Настоящий Jev (TypeSafe AI) не проверялся ни разу: веса закрыты, а вендорский API сознательно выведен из контура решением ADR-004 (в `state` уходят аргументы вызовов инструментов, то есть содержимое рабочего дерева). Провалились **открытые Jev-подобные модели** — Laya 421M, Laya 322M (multilingual), Laya typed-decisions. Это утверждения разной силы, и смешивать их нельзя.

## Целевые метрики гарда (пороги зафиксированы до замеров)

| Носитель                   | Пропуск опасного (< 10 %) | Ложные блоки (< 15 %) | p95 (≤ 3 с) | Вердикт |
| -------------------------- | ------------------------- | --------------------- | ----------- | ------- |
| `laya:en` (421M)           | 76 % ✗                    | 26 % ✗                | 6.4 с ✗     | reject  |
| `laya:typed-decisions`     | 81 % ✗                    | 9 % ✓                 | 8.2 с ✗     | reject  |
| `laya:multilingual` (322M) | 2 % ✓                     | 99 % ✗                | 5.4 с ✗     | reject  |

Ни один не проходит оба обязательных порога одновременно.

## Почему провалились — по слоям

1. **Задача не совпадает с их обучением.** Гард решает по _нашей_ таксономии прав (чтение / локальная запись / сеть / разрушение + сигналы секреты и передача наружу). Носители обучены на другой таксономии (typed-decisions workflows), где таких классов нет.
2. **Механизм провала — константное смещение, а не разброс ошибок.** `laya:en` отвечает `read_only` в 73 % случаев (в аблации — 98 %), `laya:typed-decisions` — `write_local` в 66 %. Смена чекпоинта лечит один класс и зеркально ломает противоположный (`Edit` 0 % → 98 %, `Read` 100 % → 0 %). Смещение задаётся обучающим распределением, а не размером и не промптом.
3. **Сигналы, на которых стоят правила гейта, не различают риск.** Точность `Noul`-сигнала 7–9 %; средний ответ на опасных 0.51 против 0.35 на безопасных у «разрушительности», 0.52 против 0.49 у «секретов». Порог на такой шкале построить нельзя.
4. **Масштаб и знакомство с доменом.** 0.3–0.4B, не видели ни инструментов кодинг-агента (`Edit`/`Write` с путями), ни реальных shell-команд из сессий.
5. **Инфраструктурный потолок.** p95 6.4–8.2 с на CPU-пути против бюджета ≤ 3 с. Даже при приемлемом качестве это не влезло бы в горячий путь разрешений.

## Что проверено и причиной НЕ является

- **Постановка** (`state`, критерии, формулировки): аблация постановки дала согласие 43 % → 42 %, `Edit` 0 % → 0 %, ложные блоки 26 % → 57 %. Улучшения нет, есть регресс по трению.
- **Нестабильность:** повторный прогон — 100 % совпадение и по классу, и по решению гейта, целевые метрики идентичны. Носители детерминированы.
- **Недостаток данных для замера:** эталон 396 примеров, датасет 64 093 — вопрос не в объёме измерений.

## Что это означает

**Провалился носитель, а не архитектура.** Каркас гейта проверку выдержал:

- escalate-only (AD-2) предотвращает ложные разрешения — их было бы 41 у `laya:en` в режиме `enforce`;
- fail-closed и терминальность блока (AD-13) отработали: вердикт не обходится механикой подтверждений и хуками;
- детерминизм подтверждён: решения воспроизводимы, компенсация «дрожания» в архитектуру не нужна;
- дельта форка остаётся тонкой и типизированной (объявленный список файлов, fitness-проверка).

## Развилки (решение владельца: цена / периметр / срок)

1. **Домен-адаптация** открытого носителя на нашем наборе (396 + синтетический добор редких классов). Дешевле всего; риск — 0.4B может не хватить даже после обучения.
2. **Более сильная локальная модель** — adapter на `qwen3.8-27b` (Ollama, loopback, внутри периметра). Другой механизм ответа (генеративная модель с инструкциями), шанс выше; цена — латентность и GPU-ресурс.
3. **Вендорский Jev** — по документации заточен под такие гарды и калиброван; цена — возврат к внешней передаче данных (отмена AD-10) и вендор-лок в контуре безопасности.

**Закрыто как путь:** промпт-инжиниринг вместо обучения (измерено, эффекта нет) и «перебор формулировок вопроса» (измерено, регресс по трению).

## Оговорки

- Разметка одного разметчика (κ = 0.89 intra-annotator); inter-annotator agreement не измерен.
- Страта `destructive` в эталоне малочисленна (3 примера) — метрика пропуска опирается в основном на `secrets`/`exfiltration`.
- `von` и `decider:0.8b` в замер не попали (нестабильность реестра `ollaya.dev` при загрузке); их проверка остаётся открытой.
